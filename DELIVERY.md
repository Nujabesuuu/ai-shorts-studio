## 1. Декомпозиція

Патерн — **конвеєр + ітерація + маршрутизація за умовою**: одиниці контенту незалежні
(звідси `iteration`), а рішення «ремонтувати чи ні» ухвалюється по кожній окремо
(звідси `if-else`). Кожна нода купує одну з трьох цінностей.

| # | Нода | Тип | Вхід | Вихід (типізовано) | Цінність |
|---|---|---|---|---|---|
| 1 | Start | `start` | niche, platform, formats, n_items, flow_version | — | контракт входу + мітка прогону |
| 2 | Get Rows · projects | `tool` | — | `json` | список ніш |
| 3 | Ніша → проєкт | `code` | `json`, niche | `project_id`, `row_filter`, `resolve_note` | **швидкість**: тригramна схожість замість LLM, 0 токенів |
| 4–6 | Get Rows · day2_topics / day1_trends / day3_content | `tool` | `row_filter` | `json` | джерела + список «не повторюй» |
| 7 | Prepare briefs | `code` | 3×`json` | `briefs[]`, `gate` | **швидкість**: каскад джерел і дедуп детерміністично |
| 8 | Iteration · по брифах | `iteration` | `briefs[]` | `output[]` | **швидкість**: `parallel_nums: 10` |
| 8a | Compact brief | `template-transform` | `item` | `output` | **токени**: зріз вхідного контексту |
| 8b | **A1 · Продюсер** | `llm` t=0.85 | бриф | **`structured_output: ContentDraft`** | **навички**: сценарій під формат |
| 8c | **A2 · Критик** | `llm` t=0 | draft + бриф | **`structured_output: QualityVerdict`** | **незалежна перевірка** з цитатами-доказами |
| 8d | Потрібен ремонт? | `if-else` | `verdict` | true/false | **швидкість**: 3-й виклик лише кому треба |
| 8e | **A3 · Ремонтник** | `llm` t=0.3 | `fix_list` + draft | **`structured_output: ContentPatch`** | **токени**: патч полів, не регенерація |
| 8f | Злиття гілок | `variable-aggregator` | 2 гілки | `output` | єдиний вихід ітерації |
| 8g | Assemble · одиниця | `code` | draft+verdict+patch | `item` | застосування патча без моделі |
| 9 | Merge · score · rows | `code` | `output[]` | `rows_json`, `avg_score`, `by_criterion` | **швидкість**: зважена рубрика без LLM |
| 10 | Є що зберігати? | `if-else` | `gate` | true/false | не смикати запис даремно |
| 11 | Запис у day3_content | `http-request` | `rows_json` | `status_code` | **коректність**: bulk-insert у PostgREST, 0 токенів |
| 12–13 | Get Rows · перевірка + Перевірка запису | `tool`+`code` | `run_id` | `saved`, `missing` | **незалежна перевірка** факту запису |
| 14 | Telegram · звіт | `http-request` | `tg_payload` | `status_code` | доставка статусу |
| 15–16 | Готово / Нічого не згенеровано | `end` | зведення | — | два виходи |

**Типізованих hand-off'ів — 3** (мінімум 2), усі через `structured_output`:
`A1 → A2` (`ContentDraft`) · `A2 → if-else → A3` (`QualityVerdict`) · `A3 → Assemble`
(`ContentPatch`). Перевірено програмно: `dify/validate_dsl.py` падає, якщо на
`structured_output` посилаються без схеми або прапорця.

## 2. Рубрика

| Критерій | Вага | Захист від інфляції |
|---|---|---|
| `traceability` | 25 | без дослівної цитати в `evidence` — стеля 60 |
| `production_ready` | 25 | немає таймкоду в кадрі — стеля 60 |
| `hook` | 20 | загальна фраза без конкретики — стеля 55 |
| `format_fit` | 15 | кадрів або тривалості поза межами формату — стеля 50 |
| `uniqueness` | 15 | збіг кута подачі — стеля 40 |

`quality_score = Σ(бал × вага)/100` рахує **`code`-нода, не модель**. Загальна стеля 95,
вище пускає лише цитата. У попередньому прогоні цієї бази критик ставив 100/100/91/100 —
рубрика, яка всім дає стелю, не міряє нічого.

## 3. Таблиця «до/після»

Медіана по прогонах. Джерело — Tracing і Dify API, не оцінки на око.

| Прогін | Що змінили | Токени | Δ | Час, с | Δ | Бал |
|---|---|---|---|---|---|---|
| **baseline** | дамп усього контексту; критик переписує обʼєкт цілком; 3 виклики LLM завжди | 21 574 | — | 166,3 | — | 94,0 ⚠ |
| **iter1** | конвеєр з LLM-агентом запису (`create_a_row`) | 37 839 | +75,4 % | 32,3 | −80,6 % | 81,8 |
| **final** | стиснутий бриф · критик лише оцінює · точковий ремонт · bulk-insert замість агента | **18 887** | **−12,5 %** | **11,3** | **−93,2 %** | 84,4 |

**Час — ціль узято з запасом, −93 %.** Внесок дали паралельна ітерація і зникнення трьох
послідовних LLM-викликів на кожну одиницю.

**Токени — ціль −30 % НЕ взято, вийшло −12,5 %.** Причина конкретна й видима в даних:
у фінальному прогоні ремонт знадобився **всім 4 одиницям із 4**, тому головний важіль
економії — пропуск третього виклику через `if-else` — не спрацював жодного разу. Важіль
тут не в промптах, а в якості: більша частка `verdict = pass` автоматично зрізає токени.
Це і є зміст наступної ітерації.

⚠ **Бали baseline і final не на одній шкалі.** У baseline оцінки виставляє та сама нода,
що переписує контент, — вона грає сама із собою. У final оцінює незалежний критик, який
контенту не пише. 94,0 проти 84,4 — це не «якість просіла», це «зникла інфляція». Щоб
порівняння стало коректним, виходи обох конфігурацій треба переоцінити **одним і тим самим**
незалежним критиком; поки цього не зроблено, сторінка `/runs` чесно показує «Ще не взято».

`iter1` дорожчий за baseline, бо його LLM-агент запису переписував увесь масив у аргументи
викликів. Заміна на `http-request` дала −50 % токенів відносно iter1.

## 4. Що спіймала архітектура

Три дефекти, знайдені прогонами, а не оглядом коду.

| Дефект | Хто спіймав | Корінь | Фікс |
|---|---|---|---|
| 3 згенеровано → 2 збережено | нода перевірки запису | LLM-агент робив менше викликів `create_a_row`, ніж треба | bulk-insert одним `http-request`; перевірено `HTTP 201`, 3 з 3 |
| Telegram `400 can't parse entities` | вона ж, через власний payload | legacy Markdown і непарні `_` у `format_fit`, `production_ready`, `run_id` | `parse_mode: HTML` + екранування; перевірено живим викликом, `ok=true` |
| `format_fit` 42,5 | покритерійна рубрика | у промпт летіли і призначений формат, і формат із Дня 1 — вони суперечили | підказку Дня 1 позначено як «про подачу»; після фіксу 85,0 |

Перші два спіймали саме ті ноди, які найлегше було б назвати зайвими. Без них прогін
виглядав би зеленим, поки третина контенту не доїжджала до бази.
Регресії закриті: `python3 dify/test_code_nodes.py` — 44 перевірки.

## 5. Рефлексія

Патерн — конвеєр з ітерацією та умовним ремонтом. Обрав його не тому, що він складніший
за лінійний, а тому, що робота тече саме так: одиниці контенту незалежні, а рішення
«ремонтувати чи ні» ухвалюється по кожній окремо. Це дало паралелізм і структурний важіль
економії замість косметичного скорочення промптів.

Злив я роботу, яку модель робила даремно. Критик перестав переписувати обʼєкт і віддає
лише бали з доказами та список правок. Ремонтник патчить окремі поля. Дамп усього
контексту замінив стиснутий бриф. Скоринг, дедуп і вибір джерела переїхали в `code`-ноди:
рішення, яке можна порахувати, не має коштувати токенів. Найбільше дав запис — LLM-агент,
що викликав `create_a_row` по рядку, не купував нічого, чого не купує один HTTP-виклик,
зате платив токенами і мовчки губив дані.

Межа проходить по незалежному критику. Спокусливо злити його в продюсера як самоперевірку —
baseline саме так і робить, і його бали одразу стають недостовірними: 94 проти 84 у чесного
критика. Другий рубіж — нода перевірки запису: без неї «агент сказав ок» підміняє факт
наявності рядків у базі, і саме вона показала втрату третини контенту. Обидві ноди дорогі,
обидві лишаються. Різати далі означає перестати бачити власні помилки.

## 6. Як відтворити

```bash
cd ai-shorts-admin && npm run dev
```

Імпорт у Dify: Studio → Create App → Import DSL File → `dify/day3_final.public.yml`
→ у Environment Variables впишіть `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `SUPABASE_URL`,
`SUPABASE_KEY` → **Publish**. Версію з уже підставленими ключами `npm run dsl` збере локально
з `ai-shorts-admin/.env.local` (у git вона не потрапляє).

```bash
node ai-shorts-admin/scripts/collect-runs.mjs --hours 6
```

Перегенерувати й перевірити DSL — `npm run dsl`; тести code-нод —
`python3 dify/test_code_nodes.py`.
