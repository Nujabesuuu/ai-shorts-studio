# Day 4 · Відео з бренд-буком — запуск за 6 кроків

Флоу: сценарій Day 3 → бренд-бук (RAG) → 4 межові кадри (nano banana) →
3 сегменти Veo 3.1 по 8 с зі спільними кадрами на стиках → VTT-субтитри →
черга публікації → **затвердження людиною в адмінці**.

## Один раз — налаштування

1. **База знань.** Dify → Knowledge → Create → завантажте
   `Knowledge_CaseA_SocialMedia.md`. Chunking: **по заголовках `##`**,
   ~500–800 символів, **high-quality** (так радить сам файл).

2. **Імпорт флоу.** Studio → Create App → Import DSL File →
   `dify/day4_video.yml`. Цей файл зі своїми ключами збирає `npm run dsl` з
   `ai-shorts-admin/.env.local` (у git його немає). Або імпортуйте
   `dify/day4_video.public.yml` і впишіть `SUPABASE_URL`, `SUPABASE_KEY`,
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` у Environment Variables.

3. **Привʼязати базу.** Відкрийте ноду **«Бренд-бук (Knowledge)»** → виберіть
   свою базу з кроку 1 (плейсхолдер замініться). Це єдина ручна правка:
   Knowledge Base не переноситься через DSL.

4. **Авторизувати плагіни.** Нода Veo (будь-яка з трьох `V1–V3`) → якщо
   просить ключ — вставте свій Gemini API key (той самий, що в Gemini-плагіні).
   Перевірте, що параметри нод V1–V3 підхопились (модель, 9:16, 8 с);
   якщо якесь поле порожнє — виберіть руками, це 2 хвилини.

5. **Publish** → **API Access → API Key** → скопіюйте в
   `ai-shorts-admin/.env.local` рядок `DIFY_KEY_DAY4=app-…` → перезапустіть
   `npm run dev`.

## Використання (щоразу)

6. Адмінка → **Контент · Day 3** → відкрийте сценарій → праворуч блок
   **«day 4 · відео»** → оберіть «З бренд-буком» → **Зробити відео**.
   3–6 хвилин — і вас перекине на сторінку відео; у Telegram прийде звіт.

Далі на сторінці відео: перегляд сегментів як одного ролика із субтитрами →
**«Склеїти в один файл»** (ffmpeg локально, без перекодування) →
**«Затвердити»** — це і є гейт перед публікацією; слот у черзі — наступні
18:00 Києва.

## Порівняння «з RAG / без RAG» (артефакт здачі)

Той самий сценарій, два запуски: один «З бренд-буком», один «Без бренд-буку».
На сторінках обох відео знизу праворуч — картка «бренд-бук»: у RAG-версії
видно, які правила застосовано; у версії без RAG — «бренд-бук не підключався».
Скріншоти цих двох сторінок = здача «до/після».

## Чому так, коротко

- **Кадри N+1:** сегмент i отримує кадр i як перший і кадр i+1 як останній —
  стики виходять неперервними. Граф розгорнуто на фіксовані 3 сегменти
  (24 с), бо ітерація Dify не передає файли між елементами.
- **Субтитри окремо:** таймінги і войсовер уже є в сценарії Day 3 —
  code-нода складає VTT за 0 токенів; укр озвучку у відео-моделі не пхаємо.
- **Склейка в адмінці:** Dify не вміє ffmpeg; локальний `ffmpeg-static`
  зшиває сегменти в один mp4 за секунди й без вотермарок.
- **Запасний план ТЗ:** якщо бренд-бук неповний, директор не вигадує —
  лишається в безпечних межах і пише прогалину в `missing_from_brandbook`
  (видно в картці «бренд-бук» і в Telegram-звіті).

## Якщо щось пішло не так

| Симптом | Причина → дія |
|---|---|
| «Workflow not published» | натисніть Publish у Studio |
| Сегменти не грають в адмінці | запуск був із Studio, тимчасові посилання протухли → перезапустіть кнопкою з адмінки |
| Нода Veo червона: quota/permission | вашому Gemini-ключу потрібен платний тариф для Veo — перевірте на aistudio.google.com |
| Кадри «не в стилі» | перевірте, що нода «Бренд-бук (Knowledge)» привʼязана до бази (крок 3) |
